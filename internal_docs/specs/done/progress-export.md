# Progress export and import, merged — idea (owner, 2026-10-13)

> Part of the project notes — the index is [internal_docs/README.md](../../README.md).

**The wish:** the progress is saved to a file that the user can export from the app and open in the app on another device — when moving to a new phone, or from the web version to the mobile app. **Importing merges** the file into what the device already has (owner: "exactly a merge"), never replaces it: someone who trained on the web and on the phone ends up with both.

**State:** done in **0.9.11** (branch `session/2026-10-17-progress-export`), the Health offer included (owner, 2026-10-17). How it works now: [platform.md § Progress file](../../reference/platform.md#progress-file-0911).

**Before it:** everything lived in seven Hive boxes on the device ([data-hive.md § Hive boxes](../../reference/data-hive.md)): the profile, skill progress, the workout log, achievements, own routines, branches and courses. Nothing leaves the device; the web version keeps its data in the browser (IndexedDB of `pupptmstr.github.io`). An iPhone restored from a backup or Android's Auto Backup bring the files along, but neither covers web ↔ app, iOS ↔ Android or a phone set up as new.

## Flow

- **Settings → "Your data":** "Save progress to a file" and "Add progress from a file".
- **Export:** the whole state as one file (`treniday-progress-<date>.json`) — the share sheet on iOS / Android (save to Files, send to yourself), a download in the browser.
- **Import:** pick the file → the app shows what the merge will change — "+12 workouts, +340 SP, rank Athlete → Champion, streak 9 → 14 days, 3 new achievements, Push moves to stage 5, 2 own branches" → confirm → merge → the new achievements are shown as earned.
- **Both devices equal:** merge A into B, then export from B and merge into A. Merging is idempotent, so a file imported twice, or a round trip A → B → A, adds nothing the second time.

## Merge rules (as built)

| Data | Rule |
|------|------|
| **Workout log** | Union. A workout is identified by its `WorkoutLog.date` — the local time it **ended** (`_finishWorkout` writes `now`), to the millisecond, since Hive keeps milliseconds and a log still in memory has microseconds — with its course and duration, so the same workout coming back is not added twice. Every log keeps the SP it earned, except the one below. |
| **SP and rank** | SP only comes from workouts, and each log stores `spEarned`: SP = this device's SP + what the merge changes in the log (the new logs' SP, less what a demoted log of this device gave up) — not Σ of all logs, since older data or the debug screen's logs may not add up. The rank follows from SP (`RankExtension.fromSP`); the decay from the last workout of the merged log. |
| **Two "first workouts" on one day** | **Owner, 2026-10-17:** the one with more SP keeps its full SP and stays the first of the day; the other becomes a repeat (bonus) workout and its SP is counted again as a repeat one would earn it — no ×1.5 for the first of the day, then half (`ProgressMerge.bonusSpOf`: from its exercises when they still give exactly its SP as a first workout, else a third of it, the same up to rounding). On a tie this device's stays first. Only days the file adds a first workout to are touched. (The owner first chose to keep both as earned, then changed it the same day: "a little more is fine" → the fair count.) |
| **Streak and freezes** | When the file adds workouts: recomputed by replaying the merged training days through `StreakService` — a day counts when its earliest first-of-day workout did real work (SP, or a set of a real exercise), as in `_finishWorkout` — freezes used and earned as the rules give them, and the `freezeUsed` / `freezeEarned` marks of the logs (the calendar's) set to match. Never below what a device knew: a device whose profile has a later last day than the log, or a longer streak on the same last day, keeps its streak and freezes. `longestStreak` = the largest of the replay and both stored values. When the file adds no workout, the streak stays as it is. |
| **Skill progress** | Per branch the one that is further along: stage first, then the step within the stage in the order `ProgressionService` takes them (amount → sets → rest → challenge) — a pure comparison function. `lastProgressedOn` = the later of the two, so a branch that moved today on either device does not move again today. |
| **Achievements** | Union, the earliest date of each; then the achievement checks run on the merged state (combined totals can unlock new ones). |
| **Own routines, branches, courses** | Union by id (ids are microsecond timestamps, unique across devices). The same id on both: this device's copy stays (`lastRunAt` = the later). Look-alike copies made separately on two devices stay as two; the user deletes one. |
| **Settings and profile** | This device's settings stay (theme, language, reminders, sounds, haptics, Health, pull-up bar, goal, workout size). The name comes from the file only if this device has none. Active courses: the union, so a course trained on the other device shows up; the selected course stays. `lastSeenReleaseVersion`: the newer. |
| **Health** | **Built (owner, 2026-10-17: "but check that there are no such workouts at that time").** After the merge, if this device writes workouts to Apple Health / Health Connect, the app offers to add the imported workouts there. It writes only those the health store does not already hold at that time (it reads the workouts of that range first), so a workout that reached Health from the other phone is not doubled. As built: "already holds" = any workout of any app overlapping the file's workout in time (`HealthImport`); a failed read writes nothing. New permissions: `READ_EXERCISE` on Android (the Play declaration gets a fourth justification — [store-listing.md](../store-listing.md#health-apps-declaration-and-health-connect)), workouts in the iOS read set (`NSHealthShareUsageDescription` in five languages). The plugin's Android workout read also reads distance, energy and steps, so `MainActivity.kt` reads the sessions itself. Health Connect on Android ≤ 13 reads 30 days back at most: older workouts of the file are left out, and the user is told. Asked on the way (owner): the kind of workout follows the course (strength / flexibility / yoga, with their MET) — and Android had never received a workout, the type it was sent exists on iOS only. |

## Technical notes

- A versioned JSON format of our own (`formatVersion`, `appVersion`, `exportedAt`, then each box), written by explicit codecs per model — not the Hive binary files, so the format survives Hive field changes and works across platforms. Workout days stay calendar days: the day of a log is derived with `calendar_days.dart` in the device's time zone, so the export stores the local date and time as recorded.
- The merge is a pure function `merge(local, imported, now) → (merged, summary)` with tests: round trip export → import → equal; idempotence (merge twice = merge once); same-day workouts on both sides; a streak joined across the two devices' days; skill progress ahead on either side; achievements unlocked only by the combined totals; own content with the same and different ids.
- Import refuses an unknown `formatVersion` and anything the models cannot hold — a branch, course, rank or set type this version does not know, a stage beyond a branch's last ("update the app first"). **Not** the version number itself (changed while building): the web build deploys with every merge and is usually newer than the store app, so refusing every newer `appVersion` would block the main case, web → app. Unknown exercise and achievement ids are kept (the screens skip unknown ids, and an old device holds retired achievements of Friends). Everything is validated before writing; the write goes box by box (Hive has no transaction across boxes) and on a failure the old state is written back. After it: the widget snapshot, `scheduleAll()` for the notifications, the providers invalidated.
- Packages: `share_plus` (the share sheet; on the web it falls back to a download by itself) and `file_selector` (flutter.dev's picker: a document picker on iOS with no photo-library code, unlike `file_picker`), a download through `package:web` in a computer's browser. Context7 was not available in the session; the APIs were read from the packages' sources.
- The privacy policy gets a line: the file holds the user's progress and goes wherever the user sends it.

**Done when:** the owner trains on the web and on a phone, exports from the web, adds the file on the phone and sees one history with both workouts, the SP of both, one streak over both devices' days, the further stage of each branch and every achievement — and adding the same file again changes nothing.
